# 部署指南（跟着做，约 10 分钟）

做完这五步，你就有：**电脑上一个网址**、**手机桌面一个图标**、**两端数据自动同步**、**每天 8:00 和 21:00 的提醒**。

需要准备：一个 GitHub 账号、一台电脑、一部 Android 手机（iPhone 也适用，只是「添加到主屏幕」按钮位置不同）。

---

## 第 1 步：把程序放到 GitHub Pages（约 4 分钟）

GitHub Pages 是 GitHub 提供的免费网页托管，程序放在上面，电脑和手机都能用网址打开。

### 1.1 新建仓库
1. 打开 [github.com](https://github.com) 并登录。
2. 右上角 **+** → **New repository**。
3. 填写：
   - **Repository name**：`schedule`（或任意英文名，会出现在网址里）
   - 选择 **Public**（免费版 Pages 只能用于公开仓库；这没关系——**你的任务和积分数据不在仓库里**，它们在下面单独创建的一个私有 Gist 里）
   - 勾选 **Add a README file**
4. 点 **Create repository**。

### 1.2 上传程序文件
1. 进入刚建好的仓库，点 **Add file** → **Upload files**。
2. 在电脑上打开 `F:\日程表` 文件夹，选中下面这些项目和文件夹，一起拖进网页的上传区：

   ```
   index.html
   styles.css
   app.js
   sw.js
   manifest.webmanifest
   404.html   （可选：网址打错时给个友好提示并回首页）
   js         （文件夹）
   icons      （文件夹）
   ```

   > 也可以顺便把 `README.md`、`部署指南.md`、`screenshots`、`test`、`tools` 拖进去（不影响运行，`README.md` 会覆盖仓库里那个空的）。
3. 页面下方点 **Commit changes**。
4. 上传完成后，仓库里应该能看到 `index.html`、`js/`、`icons/` 等，**目录结构要和本地一致**。

### 1.3 打开 Pages
1. 在仓库里点 **Settings**（设置）→ 左侧栏找到 **Pages**。
2. **Source** 选 `Deploy from a branch`；
   **Branch** 选 `main`，右边目录选 `/ (root)`，点 **Save**。
3. 等 1~2 分钟，刷新这个页面，顶部会出现一行网址：

   ```
   https://你的用户名.github.io/schedule/
   ```

4. 在电脑浏览器打开这个网址 → 应该看到「学习积分日程表」→ **把这个网址收藏起来**。
   建议先在电脑上点几下熟悉一下，再往下走。

> **如果打不开**：等 3 分钟再刷新；确认仓库是 Public；确认 Branch 选的是 `main` + `/ (root)`；确认仓库根目录有 `index.html`。
> **注意网址一定要完整**：必须是 `https://你的用户名.github.io/仓库名/`（结尾有斜杠，仓库名区分大小写）。地址栏里不要多出别的字符——多一个字符就会跳到 404 页（上传了上面的 `404.html` 的话，它会自动带你回首页）。

## 第 2 步：创建同步用的 Token（约 2 分钟）

Token 相当于一把「只允许读写你自己 Gist」的钥匙，程序靠它把你的数据同步到云端。

1. GitHub 右上角头像 → **Settings**。
2. 拉到最底部，点 **Developer settings**。
3. 点 **Personal access tokens** → **Tokens (classic)** → 右上 **Generate new token** → **Generate new token (classic)**。
4. 填写：
   - **Note**：`学习积分日程表同步`
   - **Expiration**：选 **No expiration**（永不过期；想更安全可以选 90 天，到期重新生成一次）
   - **Select scopes**：**只勾 `gist`**，其它一律不要勾。
5. 点最下方 **Generate token**。
6. 页面会显示一串 `ghp_` 开头的字符 → **立刻复制**（只显示这一次，离开页面就看不到了）。

### 粘贴到程序里
1. 电脑上打开你的网址 → 底部/左侧点 **设置** → 找到 **☁️ 多设备同步（GitHub Gist）**。
2. 把 Token 粘进 **GitHub Token** 输入框。
3. 点 **测试 Token** → 显示「Token 有效 ✅ 你的用户名」就成功了。

> **安全提示**：Token 只保存在你这台设备的浏览器里（不会上传到别的地方），它只能访问你的 Gist。别人即使知道你的网址，也看不到你的数据。

---

## 第 3 步：创建数据 Gist 并上传（约 1 分钟）

1. 还在「设置 → 多设备同步」里，点 **创建新 Gist 并上传**。
2. 成功后：
   - **Gist ID** 会自动填好（一串字母数字）；
   - 状态行显示「已创建 Gist：xxxx（手机上填同一个 ID + Token 即可）」。
3. 点 **立即同步** 确认一次，看到「同步成功」即可。

> 想手动创建也行：[gist.github.com](https://gist.github.com) → 文件名填 `study-schedule-data.json`、内容随便写 `{}` → **Create secret gist** → 复制地址栏最后那串 ID → 填进程序的 Gist ID → 点「立即同步」。

**到这里电脑端就完全可用了。** 下面把手机接上。

---

## 第 4 步：手机装成 App 并同步（约 2 分钟）

以 Android + Chrome 为例：

1. 手机 Chrome 打开同一个网址：`https://你的用户名.github.io/schedule/`
2. 右上角 **⋮** → **添加到主屏幕** / **安装应用** → 确认。
3. 桌面出现图标，点开是全屏应用（没有浏览器地址栏）。
4. 进入 **设置 → 多设备同步**，填入**完全相同的 Token 和 Gist ID** → 点 **立即同步**。
   - 出现「两边已一致」或「已合并云端改动」就成功了。
5. 顺手点一下 **申请通知权限** 并允许通知。

> **重要**：手机千万不要点「创建新 Gist」，否则会生成第二个数据文件。手机上只填 Token + Gist ID，然后点「立即同步」。

iPhone（Safari）：打开网址 → 底部「分享」按钮 → **添加到主屏幕** → 之后从桌面图标打开，再按上面第 4 步填 Token 和 Gist ID。

---

## 第 5 步：让提醒绝对准时（推荐，约 1 分钟）

网页通知只在程序打开时可靠（手机系统会冻结网页）。想要雷打不动的提醒，用手机自带日历：

1. 电脑或手机打开程序 → **设置 → 数据与备份 → 导出日历 .ics**。
2. 手机上打开这个 `.ics` 文件 → 选择用「日历」打开并导入。
   - 里面包含：**所有带具体时间的任务**（各自提前 10 分钟提醒）+ **每天 8:00 和 21:00 的固定提醒**。
3. 以后新增了「带时间」的任务，重新导出导入一次即可（会形成新的日程，不重复的不会冲突）。

> 想改提醒时间：设置 → 🔔 每日提醒 → 改「早上提醒时间 / 晚上复盘时间」，再重新导出 .ics。

## 日常怎么用

**每天早上**打开「今日」：看今天要做什么、总共能拿多少分。
**做完一项**点左边的方框：立刻加分，弹出「+40 分（含连击 +15%）」，画面上会撒花。
**专注学习**点番茄钟的开始：25 分钟一段，每段 +5 分，结束自动提醒休息。
**没完成任务**：不扣分，逾期任务会单独列在「逾期未完成」区域，第二天补做照样得分（记在实际完成那天）。
**攒够积分**去「商店」兑换奖励，兑换后可以随时撤销退回积分。
**每周日**看「统计」：本周得分 / 1500 分目标、完成率、和上周比、分类投入、打卡热力图。

### 分值怎么定才合适（参考你 1500 分/周 的尺度）
| 任务 | 建议分值 |
| --- | --- |
| 背单词、听力 15 分钟 | 15 分 |
| 口语 / 听力练习 | 20 分 |
| 看技术文档 / 教程 | 25 分 |
| 看网课一节、刷题 20 道 | 30 分 |
| 复习一章、写课后作业 | 35~40 分 |
| 写代码 / 刷算法题 | 40 分 |
| 青协值班 / 会议 | 50 分 |
| 毕设 / 项目推进 2 小时 | 80 分 |

每天做 7~10 项、拿 200 分左右，一周正好 1500 分。**前两周先跑一遍，觉得太松或太紧再去设置里调数字**（分值、周目标、连击加成都能改，历史记录不受影响）。

## 常见问题

**Q：手机上看到的数据和电脑不一样？**
两端都点一次「立即同步」。同步逻辑是「先拉云端 → 合并 → 谁落后就把结果写回去」，两边的任务和积分都会保留。

**Q：会不会把数据弄丢？**
不会。同步是合并而不是覆盖；每条记录都带更新时间，同一条以较新的为准；删除也有记录，不会「删了又复活」。稳妥起见建议每周点一次「导出数据备份（JSON）」，文件存到网盘。

**Q：清了浏览器数据 / 换电脑了怎么办？**
数据默认存在浏览器本地，清缓存会没——但云端 Gist 里还有。填回 Token + Gist ID，点 **仅下载（覆盖本机）** 就能恢复。

**Q：Token 泄露了怎么办？**
去 GitHub → Settings → Developer settings → Tokens (classic) → 撤销那个 Token，重新生成一个粘进程序即可。

**Q：只想在电脑上用，不想同步？**
完全可以。不填 Token 和 Gist ID 就是纯本地版，所有功能照常。

**Q：仓库是公开的，别人能看到我的任务吗？**
看不到。仓库里只有程序代码（HTML/CSS/JS）；你的任务、积分、兑换记录都在你自己的 **secret Gist** 里，需要你的 Token 才能读写。程序也没有任何第三方统计或数据上报。

**Q：能改成我自己的名字和颜色吗？**
可以。设置 → 🎨 外观：改应用名称、主色调（8 种）、浅色/深色/跟随系统。

**Q：手机上的通知没响？**
网页通知受系统省电策略影响。请务必按第 5 步把 `.ics` 导入手机自带日历，那一套提醒最可靠。

**Q：能和朋友一起用吗？**
当前版本是单人使用的（一份数据 = 一个 Gist）。想在第二个人手机上用，就用另一个 GitHub 账号 + 另一个 Gist。

## 以后想改程序怎么办

程序就是普通网页，改完文件在仓库里覆盖上传即可（或者装个 GitHub Desktop：Clone 仓库 → 改文件 → Commit → Push）。改完记得在浏览器里 **Ctrl + F5 强制刷新**，Service Worker 会更新缓存。

自测命令（需要 Node.js）：

```bash
node test/selftest.js      # 核心逻辑 141 项断言
```

界面自测：浏览器打开 `test/smoke.html`，页面顶部会输出一轮自动交互的结果。

# 附录 A：以后改了文件，怎么更新到线上（覆盖上传）

**先判断自己是不是已经部署过**：
- 如果你已经有了 `https://你的用户名.github.io/schedule/` 这个能打开的网址 → 已部署，按下面 6 步覆盖上传；
- 如果还没有这个网址 → 说明还没部署，直接回到上面「第 1 步」做一遍即可，第一次上传的就是最新文件，不存在"覆盖"。

### 6 步覆盖上传（网页版，最省事）

1. 浏览器打开你的仓库：`https://github.com/你的用户名/schedule`
   （看不到页面上方的 **Add file**？确认已登录 GitHub，并且这是你自己的仓库。）
2. 点 **Add file** → **Upload files**。
3. 电脑上打开 `F:\日程表` 文件夹，**按住 Ctrl 依次点选**需要更新的文件，例如这次是这 4 个：

   ```
   index.html
   styles.css
   app.js
   sw.js
   ```

4. 把它们**拖到网页中间那个虚线框**里（框里写着 *Drag files here to add them to your repository*）。
   - 拖进去后，框下方会列出这些文件名；
   - 文件名和仓库里已有的同名 → 提交后就是**覆盖**，不会产生重复文件。
5. 往下拉到 **Commit changes**：
   - 第一行说明可以填 `修复样式缓存` 之类（不改也行）；
   - 点绿色的 **Commit changes** 按钮。
6. 等 1~2 分钟（GitHub Pages 会自动重新部署）→ 回到你的网址按 `Ctrl + Shift + R`。
   - 还看到旧页面？再按一次 `Ctrl + Shift + R`；或者看页面顶部有没有橙色的「一键修复并重新加载」提示条，点它。
   - 手机：等 1~2 分钟后打开网址下拉刷新；从「添加到主屏幕」的图标进入的，同样是先打开再下拉刷新。

### 怎么确认上传成功了

- 仓库首页会显示最近一次提交是你刚刚提交的（时间戳是刚才）。
- 点开仓库里的 `styles.css`，用 `Ctrl+F` 搜 `[hidden]`，应该能看到这行：
  ```css
  [hidden] { display: none !important; }
  ```
  能看到就说明线上是最新版本。

### 另一个方法：GitHub Desktop（以后要经常改就用它）

1. 装好 GitHub Desktop 并登录 → **File → Clone repository** → 选中你的 `schedule` 仓库 → Clone 到本地任意文件夹。
2. 把 `F:\日程表` 里的文件复制进去覆盖（注意保持 `js/`、`icons/` 目录结构）。
3. 打开 GitHub Desktop，左下角填一句说明 → 点 **Commit to main** → 再点上方 **Push origin**。
4. 以后每次改完，重复第 2、3 步即可。

### 最容易搞错的三个点

1. **必须传到仓库根目录**：拖进去后文件名前面不能出现文件夹前缀；如果看到类似 `日程表/index.html` 这样的路径，说明位置错了，取消重来。
2. **不要改文件名和大小写**：`app.js` 不能写成 `App.js`，GitHub Pages 区分大小写，改名会导致页面打不开。
3. **上传完不用做别的**：Pages 会在一两分钟内自动生效，不需要重新去 Settings 里点保存。
